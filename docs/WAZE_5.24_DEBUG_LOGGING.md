# Waze 5.24 five-minute privacy-safe debug log

This is an opt-in troubleshooting build for Waze 5.24.0.1. It is intended for cases such as a white screen on startup or device-specific behaviour that cannot be reproduced locally.

## Tester workflow

1. Select **Waze 5.24** in BYD Multi Patcher.
2. Turn on the red **5-minute privacy-safe debug log** toggle.
3. Patch and install Waze normally (or save the patched APKM and install it).
4. Launch Waze and reproduce the problem. Leave it running for up to five minutes if possible.
5. Open `Downloads/BYD-Multi-Patcher/` and send the newest file named similar to `Waze-5.24.0.1-debug_<device>_<timestamp>.txt`.

The debug-patched Waze creates a new diagnostic file on every Waze launch. Reinstall a normal Waze patch with the debug toggle OFF after testing.

## Privacy: what is NOT recorded

The injected logger does **not** read or record:

- Waze or general Android logcat output
- GPS/location or coordinates
- routes, destinations or navigation history
- search text
- Waze account/user information
- contacts, messages, clipboard contents, microphone/audio, photos or other files
- Android ID, serial number, advertising ID or other unique device identifiers
- Wi-Fi/SSID, IP address, MAC address or other network identifiers
- Intent extras/contents
- text shown anywhere in the Waze UI
- exception messages, which could theoretically contain runtime/user data

The logger does not upload anything. The text file is created locally in `Downloads/BYD-Multi-Patcher/` and is shared only if the tester chooses to send it.

## What IS recorded

Only technical diagnostics generated by the injected helper itself:

- Waze version
- device manufacturer/model (not serial/device ID)
- Android version/API level
- CPU ABIs
- display resolution/density
- WebView package/version
- Waze Activity lifecycle events (created/started/resumed/etc.)
- non-text UI structure counts such as number of views/WebViews/SurfaceViews/TextureViews, window focus, dimensions and hardware-acceleration state
- Java/native memory usage and Android low-memory/trim callbacks
- main-thread responsiveness; if the main thread stalls, stack-frame names only are recorded
- uncaught Java crash exception class and stack-frame names only; exception messages are deliberately omitted

This gives useful startup/white-screen information without collecting Waze user data.

## Implementation notes

The logger is injected only when the Waze 5.24 debug toggle is enabled. A startup `ContentProvider` starts before Waze `Application.onCreate()`. It registers lightweight lifecycle/memory hooks and samples technical app state for up to five minutes. It never starts `logcat`.

The logger DEX is built as a standalone Android-framework-only DEX. The APK injector preserves all existing local Waze ZIP entry offsets/alignment, appends the modified manifest and logger DEX, discards the obsolete signing block, and then the normal BYD Multi Patcher signing path signs the rebuilt base and all splits with the same local certificate.
